# SDS 맞춤형 AI News

Sites 화면: https://jadenainews.garzette.chatgpt.site

로컬 작업 폴더: `JAPIS/sites/jadenainews`. GitHub: https://github.com/garzette0905/jadenainews (`origin`, `main`). Sites 프로젝트는 `.openai/hosting.json`의 ID를 유지합니다. Sites 공식 소스 저장소와 GitHub는 별도 원격이며, Sites 배포 후 동일 커밋을 `git push origin main`으로 동기화합니다.

## 테스트 시작

PC에는 Windows, Node.js 24 이상과 공식 ChatGPT/Codex 앱의 실행 도구가 필요합니다. 앱에서 ChatGPT 계정으로 로그인합니다. 이 폴더에서 `npm run bridge`를 실행하거나 `start-news.ps1`을 실행합니다. 폰·PC의 브라우저 또는 앱 안에서 Sites에 로그인한 뒤 **PC 앱 연결됨**이 표시되면 모델을 선택하고 **데이터 수집하기**를 누릅니다. **새로고침**은 저장된 결과만 불러오며 새 수집을 요청하지 않습니다. 폰에서는 실행 프로그램을 설치하거나 localhost에 접속하지 않습니다. PC와 폰이 같은 네트워크에 있을 필요도 없습니다.

API 키나 별도 API 과금 계정은 사용하지 않습니다. 공식 Codex App Server의 `account/read`로 ChatGPT 로그인 여부를 확인하고, 같은 실행 도구가 소유한 계정 세션으로 뉴스를 조사합니다. 프로그램이 인증 파일을 직접 읽거나 토큰을 추출·복사하지 않습니다. API 키 로그인은 거부합니다. 모델 목록은 App Server의 `model/list`에서 가져옵니다. 뉴스 조사에는 읽기 전용의 일회성 세션을 쓰며 셸·앱 커넥터·MCP·다른 에이전트·훅 기능을 제한합니다.

계정 인증과 갱신은 공식 앱 실행 도구가 관리합니다. OAuth 토큰을 Sites나 브라우저에 보내지 않습니다. `.runtime/`은 Git과 배포에서 제외합니다. 사이트 전용 서비스 연결 설정은 `.runtime/site-agent.dpapi`에 Windows CurrentUser DPAPI로 암호화합니다. PC는 Sites로만 외부 연결을 보내고 수집 요청·진행률·결과를 교환합니다. 모바일 화면은 같은 Sites 서버에만 요청하며 PC의 포트를 인터넷에 공개하지 않습니다. 사이트는 별도의 `NEWS_AGENT_SECRET`으로 PC 서비스 요청을 검증합니다. 이 값은 Sites의 비밀 환경 변수에만 보관하고 소스·브라우저에 넣지 않습니다.

PC 프로그램이 켜져 있어야 새 수집을 할 수 있습니다. 수집 후 기사·평가는 Sites R2에 사용자별로 저장되고 PC가 꺼져도 저장본은 볼 수 있습니다. 사이트에 접속하기 위한 로그인은 PC 앱의 모델 실행 로그인과 별개입니다. 폰에서 새 수집을 눌러도 모델 실행과 요금제 사용은 연결된 PC 계정에서 이루어집니다. 폰 자체에서 Codex App Server가 실행되는 것은 아닙니다. 전체 처리를 PC 없이 실행하려면 별도 실행 호스트와 인증 연결이 필요합니다.

조회 전용 사용자는 관리자의 기사와 추천 순위만 봅니다. 수집·평가·좋아하는 기사 등록·사용자 관리는 서버에서 소유자와 관리자에게만 허용합니다. 조회 계정은 저장된 목록을 볼 수 있습니다. 기사·피드백 원본은 기존 관리자의 R2 저장 경로를 유지합니다. 조회 전용 계정에서는 목록 새로고침 버튼도 숨깁니다. 관리자 권한은 서버에서 확인하며 클라이언트가 보낸 역할은 신뢰하지 않습니다.

## 뉴스 판단

14개 RSS 피드에서 최근 후보를 수집하고, 피드가 없거나 실패한 출처는 확인 한계에 표시합니다. 선택된 미확인 후보 원문은 AI 웹 조사로 보완하며 출처마다 별도 AI 세션을 추가하지 않습니다. 9to5Google을 포함한 참고 매체를 AI 조사 지침에 유지합니다. PC가 원문 본문과 최초 발행일을 직접 읽어 AI에 제공하며, 새 후보와 변경된 평가 조건의 후보만 최신순 최대 40개(20개씩 2묶음, 순차 실행) AI로 검토합니다. 같은 원문·모델·평가 조건이면 하루 동안 완료된 AI 평가를 재사용합니다. 60일 지난 평가는 AI 입력에서 제외하고 평가 요약을 400자로 제한하며, 이전 기사 목록을 각 AI 묶음에 반복 전송하지 않습니다. 직접 읽지 못한 원문은 모델의 실제 웹 검색으로 보완합니다. 사용자 제공 2026-10-12 기사 주제 30건을 제목·원문 주소·참고 목록 발행일을 유지해 21일간 별도 조회 가능하게 합니다. 원문 접근 실패 시 원문 미확인 임시 평가로 표시하며, 수집 시각을 발행일로 대체하지 않습니다. 확인된 원문은 모델 완료 여부와 무관하게 기본 분류·중요도·취향 유사도·발행일 기반 순위에 남깁니다. AI는 참고 기사 및 최신 우선 묶음의 의미 평가·요약을 보완합니다. 사용량 한도에서는 추가 AI 요청을 멈춥니다. 모델 선택에서 원문 기반 빠른 수집을 선택하면 AI 호출 없이 전체 기본 목록을 갱신합니다. 기본 평가, AI 평가, 원문 미확인 임시 순위를 화면에서 구분합니다. 숫자 계산과 결과 유효성 검사는 코드에서 수행합니다.

배점: 중요도 25, 취향 20, 기사 성격 10, 근거 5, 최신성 40, 부정 취향 최대 35 감점. 저장된 AI 배점 importance/preference(각 30점)는 계산 시 25/20점으로 정규화해 이전 데이터에도 적용합니다. 최신성은 `40 * 0.5 ** (기사 경과 시간 / 반감기)`이며 뉴스 8시간·공식 발표 18시간·리포트 48시간 반감입니다. 경과 시간당 뉴스 0.6점·공식 0.3점·리포트 0.08점을 추가 감점하며 최대 30점입니다. 수집 요청 시각에 한 번 계산해 순위·점수를 저장합니다. 화면 조회와 JSON 내려받기에서는 저장된 순위를 그대로 사용합니다.

좋아요는 읽음이 아닙니다. 동일 기사 좋아요로 자기 점수를 올리지 않도록 AI에 명시합니다. 선호는 회사·발표자·주제·종류·매체로 판단하며 14일 반감·60일 만료를 적용하도록 지시합니다. 좋아요·싫어요·평가 삭제는 저장만 하며 현재 기사·점수·순위를 바꾸지 않습니다. 다음 수집을 요청하면 그 시점의 평가로 순위를 계산하며 싫어요 URL을 제외합니다. 수집 중에 바뀐 평가는 그다음 요청에 적용합니다. 기사 URL만 등록한 경우 다음 수집 때 AI가 원문 내용을 확인합니다. 등록이 즉각적인 원문 분석 완료를 뜻하지 않습니다.

실제 원문 HTTP 접근 또는 웹 검색 도구 실행, 완료 이벤트, 원문 출처 URL, 발행일, 배점 범위를 검증한 결과만 저장합니다. 검색에 등장한 URL이라는 사실은 전문 접근과 사실 검증을 보장하지 않습니다. 발행일의 사실 여부와 의미 판단은 AI 오류가 남을 수 있으므로 시험 운영에서 확인해야 합니다. 개별 후보 오류는 그 후보만 제외하고 경고를 남깁니다. 같은 사건의 다른 원문도 별도로 조회됩니다. 참고 기사 30개는 저장 상한에서 일반 후보보다 먼저 보존하고, 화면 순위는 모든 기사에 동일한 점수 내림차순을 적용합니다. 수집 원본은 최대 250개 보관하고 화면에서는 50위까지만 점수 내림차순, 동점이면 최신순으로 표시합니다. 부분 조사에서는 기간 내 이전 검증 기사를 보존하며 이전 평가임을 경고합니다. 전체 실패·늦게 도착한 이전 결과는 기존 기사로 덮어쓰지 않습니다. RSS 접근 성공은 원문 검증 성공을 의미하지 않습니다.

## 결과 연동

`GET /api/news`는 저장된 기사와 마지막 수집 순위 JSON을 반환합니다. `GET /api/runtime`은 PC 연결 상태, `POST /api/collect {model}`은 수집 요청, `GET /api/jobs/:id`는 본인 요청의 진행 상태입니다. 사이트 로그인 사용자에게만 허용되며 계정별 기사와 피드백을 분리합니다. 동시 중복 요청, 다른 계정의 작업 조회, 만료된 실행 권한, 수집 시작 시 평가를 고정합니다. 수집 중 평가가 바뀌어도 완료한 조사를 버리지 않고 다음 요청에 반영합니다. PC 서비스의 heartbeat/claim/progress/complete는 별도 인증으로 보호합니다. 현재 JAPIS 연결은 구현하지 않았습니다.

## 로그인 환영 메시지와 사용자 관리

화면 제목은 로그인 프로필 이름으로 “OOO님. 환영합니다. 오늘의 SDS 맞춤형 AI News 입니다.”를 표시합니다. Sites가 전달한 이름은 공식 헤더의 인코딩 정보를 따라 UTF-8 디코딩하며, 이름이 없으면 등록 이름·이메일 순으로 표시합니다. 이름은 textContent로 출력합니다. 관리자는 좋아하는 기사 등록 오른쪽의 사용자 관리 버튼으로 팝업을 엽니다. 목록은 팝업을 열 때 불러오며 조회 전용 계정에는 관리 버튼이 표시되지 않습니다. 닫기 버튼과 Escape로 닫을 수 있습니다.

## 제목 편집과 화면 파일 갱신

현재 표시 대상 50개 제목은 원문 제목·요약을 대조한 편집 제목으로 즉시 표시합니다. 원문 제목과 요약의 지문이 달라지면 기존 편집 제목을 재사용하지 않습니다. 원문 제목·배점·순위는 보존합니다. 새 AI 평가에는 IT 기획자용 쉬운 제목과 영어권 회사·인물의 영어 표기, 비영어권의 한글 표기를 지시합니다. 기본 평가의 제목에는 표준 회사·인물 표기와 매체 접미사 제거를 적용합니다. 화면과 JSON recommendations는 통합 순위 50위까지 제공하며 원본 ranked는 전체를 보존합니다. HTML·JS·CSS·공유 모듈에 내용 해시를 붙여 새 배포에서 오래된 화면 파일과 섞이지 않게 합니다. 열린 화면은 브라우저 페이지를 새로고침해야 새 코드가 반영됩니다.
